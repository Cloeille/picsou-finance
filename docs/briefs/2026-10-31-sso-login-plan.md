# SSO Login Implementation Plan

> **For implementers:** work through the tasks in order. Each one ends in a green, reviewable
> state. Steps use checkboxes (`- [ ]`). Implementers do not commit; whoever runs the plan commits
> once per task.

**Goal:** let people sign in to Picsou through an external OIDC provider (Zitadel first) alongside
passwords. This covers:
- password-less accounts;
- provisioning the first admin from an IdP group;
- that group keeping admin rights in sync;
- re-authentication through the IdP for sensitive actions;
- turning password login off per account.

Nothing changes when SSO is not configured.

**Architecture:**
- A third `SecurityFilterChain` (`@Order(0)`, `/oauth2/sso/**`) runs Spring Security's
  `oauth2Login` against one lazily discovered provider, with PKCE S256, `state` and `nonce`.
- The success handler resolves the IdP identity `(iss, sub)` to an `AppUser`, syncs the role from
  the groups claim, and issues **Picsou's own cookies** through `SessionIssuer`, which is extracted
  from `AuthController`. The IdP's tokens are discarded.
- SSO sessions carry `sso_at` so they must pass through the IdP again after a window.
- A short-lived `reauth_proof` cookie gates credential changes.

**Tech stack:** Java 21, Spring Boot 3.5.16 (Spring Security 6.5.x, `spring-boot-starter-oauth2-client`
managed by the BOM), Nimbus, PostgreSQL 16 / Flyway, React 19 / TypeScript / Tailwind v4 / bun.

**Design spec:** [`docs/briefs/2026-10-31-sso-login-design.md`](./2026-10-31-sso-login-design.md).
Read it first; the security properties S1–S13 and the error codes are defined there.

## Global constraints

- **Branch:** `feature/sso-login`, from `main`.
- **Flyway:** the next free slot is **V122** (`main` ends at V121 `cic_session`). Re-check across
  every branch before merging ([CODING_RULES §4](../CODING_RULES.md)).
- **No behavior change without SSO.** With `SSO_ISSUER_URI` unset there are no SSO beans, chain or
  UI. Tasks 10 and 23 assert this.
- **Security invariants S1–S13** from the design brief must hold after every task.
- **Backend conventions:**
  - Mockito unit tests by default; MockMvc only for HTTP-level behavior; Testcontainers only for
    the end-to-end integration test (Task 23).
  - Constructor injection; no try/catch in controllers.
  - Failures as ProblemDetail with a stable `code`.
  - `LogSanitizer.safe(...)` around every IdP-supplied value.
  - New endpoints documented in `backend/docs/API.md`.
- **Frontend conventions:**
  - Every new string goes in all four locales (`fr`, `en`, `de`, `es`); `locales-parity.test.ts`
    must pass. French copy uses "vous".
  - Mobile-responsive layouts.
  - A clean `bun run build` and `bun run lint` at zero warnings.
  - Never edit `components/ui/`.
  - API calls only in `features/*/api.ts`.
- **One signing key.** Every Picsou token stays HS256 with `JWT_SECRET`.
- **Commits** follow conventional commits, one per task: `feat(auth): …`, `refactor(auth): …`,
  `test(auth): …`, `docs: …`. Doc updates ship with the code they describe.
- **Verification ceiling:** the real Zitadel handshake is only verifiable manually (runbook at the
  end). Every task is verifiable with `mvn test`, `bunx vitest run` and `bun run build`.

**Interfaces:**
- `record SsoIntent(Kind kind, String redirect, boolean rememberMe, Long userId, String activationToken, Instant startedAt) implements Serializable`,
  with `enum Kind { LOGIN, LINK, REAUTH, ACTIVATE, SETUP }` and the constant `ATTRIBUTE`, which is
  the request and authorization-request attribute key.
- `SafeRedirect.sanitize(String raw, String fallback)` accepts only paths that start with `/`.
  It rejects `//`, `/\`, control characters, and anything longer than 2048 characters.
- The chain, `@Order(0)`, `@Conditional(SsoEnabledCondition.class)`,
  `securityMatcher("/oauth2/sso/**")`:
  - `oauth2Login` with:
    - `authorizationEndpoint.baseUri("/oauth2/sso/authorization")`, the resolver and the
      repository;
    - `redirectionEndpoint.baseUri("/oauth2/sso/code/*")`;
    - `userInfoEndpoint.oidcUserService(...)`, where the service has
      `setRetrieveUserInfo(r -> userinfo URI present)`;
    - the success handler (Task 11) and the failure handler.
  - `securityContext(c -> c.securityContextRepository(new RequestAttributeSecurityContextRepository()))`,
    so nothing is stored in the session.
  - `sessionManagement` set to `IF_REQUIRED`.
  - CSRF disabled. Both endpoints are GET navigations, and `state` binds the handshake.
  - `SsoStartGuardFilter` placed before `OAuth2AuthorizationRequestRedirectFilter`.
- **Guard** on `GET /oauth2/sso/authorization/oidc`:
  - rate limit by `ClientIp.resolve`;
  - `intent` (default `login`); `redirect` through `SafeRedirect`, with a default per intent;
    `rememberMe=1`;
  - check that the provider is available (`registrationRepository.isAvailable()`);
  - per-intent checks; this task implements **LOGIN only**, which requires `setupService.isComplete()`.
    The other intents are refused with `IDP_ERROR` until Tasks 15, 17 and 18 add them;
  - on failure: 302 to the intent's error page with `ssoError=<CODE>`;
  - on success: `request.setAttribute(SsoIntent.ATTRIBUTE, intent)`.
  - It does **not** rely on `SetupFilter`, which never runs for requests this chain answers
    itself (see the design).
- **Resolver**: wraps `DefaultOAuth2AuthorizationRequestResolver`. It copies the intent into the
  authorization request's attributes and adds `prompt=login` and `max_age=0` for REAUTH. PKCE
  S256 comes from the registration, or from `withPkce()` per Task 9.
- **Repository**: delegates to `HttpSessionOAuth2AuthorizationRequestRepository`. Its
  `removeAuthorizationRequest` also stores the removed request in a request attribute, so both
  handlers can read the intent.
- **Failure handler**:
  - `authorization_request_not_found` gives `SESSION_EXPIRED`; anything else gives `IDP_ERROR`,
    with a WARN log of the sanitized description;
  - it redirects to the intent's error page, or `/login`;
  - it invalidates the handshake session.

## Manual end-to-end runbook (Zitadel)

1. **Zitadel setup:**
   - a project "Picsou" with the role `picsou-admin`, and **"Assert Roles on Authentication"** on;
   - a Web application using the Code flow with Basic authentication, redirect URI
     `https://<host>/oauth2/sso/code/oidc` and post-logout URI `https://<host>/login`;
   - the groups Action on **"Pre Userinfo creation"**. Alternatively, skip the Action and set
     `SSO_GROUPS_CLAIM=urn:zitadel:iam:org:project:roles`;
   - grant `picsou-admin` to the future admin.
2. **Fresh Picsou:** put the `SSO_*` variables in `docker/.env`, including
   `SSO_ADMIN_GROUP=picsou-admin`, then `docker compose up -d`. Open the wizard. The admin step
   shows only "Continue with Zitadel". Sign in: you land on the Security step. Finish the wizard
   and reach the dashboard.
3. On another fresh instance with the group set, `POST /api/setup/admin` gets 409
   `SSO_ADMIN_REQUIRED`.
4. **Group changes:**
   - a second user with the role gets an admin account at their first SSO login;
   - remove the role, and they are a member after their next SSO login, or within 24 hours;
   - removing the role from the only admin leaves them admin, with a WARN in the logs.
5. **Invitation:** invite a member from Admin → Members and open the link. "Activate with Zitadel"
   signs them in. Settings shows SSO linked and no password.
6. **Re-authentication:** as that member, go to Settings → Export and choose "Confirm with
   Zitadel". Zitadel asks for a new login; back in Picsou, the export downloads. Note whether
   Zitadel asked for the second factor again; that depends on its check lifetimes.
7. **Password user:**
   - link Zitadel (the password is confirmed first) and sign in once with SSO;
   - "Turn off password login"; password login now fails;
   - for an admin, `ADMIN_RECOVERY_ENABLED=true` still restores access.
8. **Remember Me through SSO:**
   - close and reopen the browser within 24 hours: still signed in;
   - with `SSO_SESSION_REVALIDATE_AFTER=2m`, after two minutes the app passes through Zitadel
     without asking anything.
9. **iOS app and claude.ai connector:** authorize, sign in through SSO in the web login, and the
   app or connector completes.
10. **IdP logout:** with `SSO_IDP_LOGOUT=true`, logging out ends the Zitadel session, so the next
    SSO click asks for credentials.
